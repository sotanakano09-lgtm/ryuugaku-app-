02 / 管理責任の切り分け

🧑‍💻 VS Code — 操作画面

ローカルのプロジェクトを開き、Codex拡張に自然言語で依頼。実装結果を確認する。VS Codeが必須というわけではないが、今回の標準作業環境とする。

✦ Codex — AIエンジニア

コードを作成・変更し、テストを実行する。プロジェクトのルールは AGENTS.md と Skills から読み込む。人間の承認が必要な操作は確認する。

⌘ GitHub — 技術の正本

コード、開発ルール、技術仕様、SkillsをGitで履歴管理。レビュー後に変更を確定し、どの仕様で実装したかを追跡可能にする。

📄 Google Drive — 業務の正本

サービスの目的、要件、業務フロー、会議の決定を管理。GitHub側に必要な技術要件を反映する。機密情報や個人情報は公開リポジトリにコピーしない。

03 / GitHub初回コミットの推奨構成

study-abroad-platform/
├── README.md                  # プロジェクト概要 / 開発の入口
├── AGENTS.md                  # Codex向け共通開発ルール
├── docs/
│   ├── system-architecture.html  # このアーキテクチャー図
│   ├── technical-spec.md         # 技術仕様（GitHub側の正本）
│   └── documentation-index.md    # Drive文書へのリンク一覧
├── .agents/
│   └── skills/                 # リポジトリ共有のCodex Skills
│       └── README.md
└── src/                        # アプリ実装（開発開始後）
重要：この図は「運用の設計案」です。GitHubとGoogle Driveの双方向同期、Drive文書のCodexへの読み込み、Skillsの自動登録は、最初から自動で行われるわけではありません。必要な認証・連携・更新手順を後で実装します。また、同じ文書の二重管理を避けるため、種類ごとに「正本」を決めます。

04 / 初期運用ルール

01 / 仕様決定

業務要件はDriveで確定し、開発に必要な内容をGitHubの技術仕様・Issueへ反映する。

02 / Skills更新

繰り返し使う開発手順はリポジトリ内の .agents/skills/ で管理し、変更履歴を残す。

03 / コード変更

Codexが変更を実施したら、VS Codeで差分を確認。テスト後にGitHubへコミットする。

04 / 情報保護

学生の氏名、連絡先、出願資料などの個人情報はGitHubの公開領域に保存しない。権限を明確にする。
